# 归位与验收

按当前任务选用与文件、引用及正式入口有关的章节。

## 电脑与项目清理的共同边界（2026-11-16）

- 五类保留标准适用于用户指定的电脑或项目整理范围；这不是把全盘文件搬进同一个目录的要求。系统、已安装软件及共享环境保持原有有效位置，个人数据即使不被项目引用也独立受保护。
- Documents、AppData、`.cache` 等可能混放多种内容，不能整目录认定可删；缓存须核实真实作用、可重建性与在用情况，旧版本、重复安装包和备份须核是否含独有内容、是否仍需恢复或离线使用。
- 容量调查只读；确认保留标准、要求迭代 Skill 均不等于清扫授权。日常候选原位登记；明确清扫后按垃圾桶 Skill 可恢复处理，永久删除另须明确授权，同盘搬移不算释放空间。
- 验收覆盖受影响的五类保留项：成果可用、源工程可继续编辑/构建、依赖与配置有效、个人数据保留、必要工具可正常使用。没有实际打开或运行的部分标待验证，不以分类完成代替验收。

## 正式接入判据与过程集中（2026-11-15 用户确认，适用于所有项目）

- 只有已接入项目正式成果、正式使用版本或正式入口的内容及其必要依赖，才算正式结果。以实际消费者和采用记录核实，不以“制作完成、已交付、测试通过、放在交付成果目录”代替正式接入。独立文档等任务以用户确认的正式成品为目标入口，不强套游戏运行入口。
- 未接入的候选代码、素材、演示、设计文档、交接说明、截图、审查报告、历史备份和恢复测试副本均属过程文件；被当前开发、恢复或审核使用时记为“过程／在用”，不能升级为正式结果，也不能据分类直接删除。原始输入资料单列保护，必要追溯证据可保护留存，但不因此改称已接入结果。未知项标“接入待核”。
- 用户只要求“过程文件放到一起”时，归并到既有过程区；用户明确“原文件、结果文件、必要工具放一起，其余过程进垃圾堆”时，按[下文两区标准](#保留区与过程垃圾堆)直接承接，不再停留于另建过程区或仅登记。两种授权均不等于永久删除。常规收尾仍限本轮；明确指定的历史范围按本次授权处理。
- 对历史路径消费者先核用途和在用情况。只读链接/共享计划等过程消费者确需兼容时，可在同盘原生搬移实体后留下明确登记的旧路径兼容入口，验证新旧入口内容相同、真实目标在本项目过程根内；文件硬链接不是永久同步机制，原子替换后须重验同实体关系。不得用兼容链接掩盖正式结果读取过程区的问题，不得绕过拒绝链接的消费者或改写不可变历史证据。当前写入、原始资料混放或无法证明兼容时，保留相关子范围并报告具体限制。
- 正式运行仍读取 `.work` 中的代码或数据时，先把真实依赖纳入保留集合，按需迁入稳定位置；不能因目录名或历史标签随过程材料搬走，也不能据一项依赖保留整个过程目录。必要运行状态和通信区一并核实。验收分别报告分类、实体迁移、兼容入口和留置项；同盘归堆不等于释放空间。

## 保留区与过程垃圾堆

- **保留集合按五类决定（2026-11-16 用户确认，替代原三类口径）**：①结果文件：正式采用的成果，沿用上文正式接入判据；②源文件：原始资料、源素材、代码、可编辑工程及必要版本身份；③必要依赖与配置：引用素材、数据库、运行数据、依赖库、构建定义、环境与账号/凭据配置；④个人数据：照片、聊天记录、账号资料、个人文档、存档等用户仍需的数据；⑤必要工具：仍需使用的软件、开发工具、脚本、插件及必要的离线安装包。工具可服务多个项目或个人用途，不以某个结果是否引用、最近是否用过作为唯一必要性依据；低频但关键的工具也保留。类别允许交叉，不按后缀或所在目录机械拆分；已安装有效依赖不能当下载缓存删除。
- **五类之外先列待清理候选，不自动认定为垃圾**：系统及仍在使用的软件正常保留；用途未知项、在途任务和必要恢复输入先保护。项目内候选、试验、独立演示、截图、设计/审查/交接报告、临时生成物、旧备份及恢复测试副本按用途核实，不因交付、旧keep标签或可供历史重跑升级为正式结果，也不因标为过程就自动可删。若用户已确认“其余过程进垃圾堆”，此范围内实际可恢复搬移已获授权，不再要求逐项重复批准或再次证明每份历史报告毫无价值；先完成保留闭包和在用检查。
- 复用原正式工程作为保留区，必要时明确其内部原件/结果/工具位置；不为呈现两区复制或重建整套工程。垃圾堆使用项目现有`.task-trash/<批次>/`或已约定位置，保持相对结构及源→目标回执。不能只建索引、只换名称或继续留在普通过程区就声称已归堆。
- 正在被真实游戏或在途工具使用的内容先保护并定位具体文件闭包，不停止用户游戏、不搬正在写入的目录；将不受影响部分先归堆，剩余范围及触发条件写明。仅历史路径/身份引用不阻止归堆；共享过程消费者确需旧路径时，可保留明确登记的兼容入口，但正式修改/构建/运行不得读取垃圾堆中的必要输入。
- 原文件和必要依赖混在过程区时先分离保留；原件的常规收尾不自动搬移，本次明确分区授权内的可恢复迁移须保留身份与内容验证。验证保留入口、关键原件/结果SHA、构建与运行依赖读取及实际搬移回执，区分静态核查与真实运行。未验证的保留闭包或未搬项不能冒称全项目完成；永久删除仍需另有明确授权。



## 开工前分区并标记

### 五个项目目录

任何会产生文件的项目，先在规划中定好项目根及五个实际落点，开工时先建齐缺少的目录，再开始制作。用户指定的现有同用途目录可直接复用，在计划里逐一写明对应路径。已有项目的固定入口、共享工具和原件可登记实际位置；新增可控产物按本规则落盘。没有文件产物的纯问答或只读调查无需建目录。

| 目录 | 内容 |
| --- | --- |
| 原材料 | 原始试卷、用户给定素材、输入数据、已有可编辑源稿。复用已归档原件时记来源和使用路径。 |
| 结果文件 | 正式交付的文档、图片、音视频、网站和可交付工程版本。 |
| 结果数据 | 正式成果读取的结构化数据、索引、数据库和必要配图数据。续做断点、恢复映射和必要回执单设子目录并标明消费者。 |
| 工具 | 仍需使用的转换、构建、验收工具及其必要配置。一次性脚本、诊断输出随所属过程批次进垃圾堆。 |
| 垃圾堆 | 草稿、临时转换、渲染预览、测试副本和日志，按任务类或工具类登记批次。使用所在盘约定的自建垃圾堆，允许映射到项目已有的 `.task-trash` 或 `99 垃圾堆`。 |

计划对每份新增文件或同用途文件组记录五类之一、实际路径、写入者和用途。垃圾堆批次以「处理中」「待核」「可清」区分状态，正在使用的过程文件继续受保护。工具强制写到固定暂存位置时，在清单写明实际路径、所属类别及归位时机。已有项目的重排按当前授权和真实引用逐批验证。

### 项目备份保留

- 在 `结果数据/备份/` 保存同一项目最近仍用得上的备份，最多五份。按可信版本记录或备份时间从新到旧核对，先确认用途与可恢复性。一个可独立恢复的版本及其配套文件按一份计。
- 已被替代且确认不承担续做、回退或恢复用途的备份，按[垃圾桶 Skill](../../trash-bin/SKILL.md)移到所在盘的自建垃圾堆，保留恢复映射。遇到超过五份且仍有独有恢复用途的，先核对如何合并或替代，再处理超额项。原始输入与唯一源文件继续按原材料保护。

### 文件落点与批次标记

- **归属只用两类**。某项业务的过程产物跟随该任务，标「任务类」，例如材料入库、整卷转换或综合题接入。软件自身安装、更新、诊断、试跑、恢复演练及工具维护产生的过程产物跟随该工具，标「工具类」。按实际服务对象归属。五类保留标准仍用于识别原件、成果、依赖、个人数据及必要工具。
- **执行者在首次写入前定落点**。原件沿用来源，正式结果、活跃断点和必要依赖按正式入口落盘。确认是临时渲染、预览、隔离测试副本、诊断采样、中间转换或临时导出的，生成时直接写已约定的垃圾堆批次。验收工具有固定在途暂存路径时按其入口写入，并记录状态和实际位置。已有项目或工具的指定位置优先。
- **同用途批次一份标记**。复用现有任务编号，记录归属类型、任务或工具名、批次、用途、所在目录、状态和证据。新批次标「处理中」，已确认结束、可重做或可舍且无正式或续做引用时标「可清」，证据不全标「待核」。混放的目录保留原标记并拆到能说明用途的子批次，原件、成果和必要证据保护原位置。可清状态仍按现有用户授权和清扫清单处理。
- **禁写盘根与禁止编号克隆**。严禁把盘符根目录（如 `C:/`、`D:/`、`E:/`）用作默认工作目录、脚本临时输出落点或便携软件解包目录，须落到项目对应目录或共享工具目录。目录或批次碰撞时，严禁自动追加 `(1)` `(2)` 等编号克隆整套目录；须先核对任务身份与内容哈希，同内容跳过或增量更新，真冲突即报错停下。多批次或 `.work` 中不得重复复制重型工具链与字体包（如 JDK、压缩字体包），统一引用公共工具路径；演示或审核录屏优先输出 MP4/WebM 等压缩格式，避免长期留存未压缩大体积 AVI。
- 工具自身的诊断、复演和验证输出放到使用者指定的工具过程区，业务任务的输出放到本项目的过程区。正式配置和运行依赖留在各自入口。
- 可用垃圾桶 Skill 的 `scripts/open-process-batch.py` 先建立目录和 `过程标记.json`。习惯使用既有等价批次标记时复用原记录。正式交付回执只链接稳定成果，清扫时按标记筛选批次，并继续执行相应的引用和在用检查。

## 先确定位置，减少事后搬动

### E盘分类保存默认

- 新任务先核项目现有位置，按文件实际用途保存。已有正式工程和在用依赖优先。
- 从生成时区分源文件、待审核材料、已确认成果和过程材料；待审核发布包不冒称已采用或已发布。提示词、生成原图、分析画面和核验记录集中到过程材料。原始输入默认原位保留，跨盘复制核对 SHA-256，不自动删除来源；Skill 安装文件留在环境可发现的 Skills 位置。
- 不据此迁移历史工程、已安装软件或共享数据，也不自动清扫。目录分类与实体迁移分别核验，候选及未知文件按垃圾桶规则标记并原位保留。

读取项目适用说明，按规划中已落实的正式接入路径与过程工作区生成文件。已接入内容保存于正式位置；尚未接入的交付候选也放过程区，复用既有任务暂存与索引。已确认是可舍或可重建的过程产物，按上文直接写入相应的垃圾堆批次。有固定暂存入口且仍有验收用途时，按工具实际路径写入并在五类清单标记。真正的续做与恢复文件落在结果数据的对应子目录，或复用已约定的固定入口。目录名“交付成果”不能决定文件性质。首次写入前确认实际路径及写入归属，不把过程截图、日志、试验脚本或整工程副本散落正式资源目录，不能只在收尾才分目录。已有固定测试工程时复用，不另复制工程；未获历史归并授权时不为整齐改已有项目目录。

- PDF、Word、图片、压缩包：按是否已接入正式成果确定位置；未接入候选放过程区，不能因确认交付就自动列为正式结果。
- 截图、渲染预览、测试日志和中间数据：按已约定的过程落点直接写入，保留归属、批次和相对结构。已确认供正式使用的素材或必要证据归正式位置。
- 代码、配置、源素材、数据库、有效依赖及最小恢复映射：按项目规定的位置保留。审计证据不是默认保留类别；调查输出、旧备份、测试样本完成用途后按任务保留策略处理，不因放在工作区就永久保留。
- 弃用或用途未确认的文件：使用[垃圾桶 Skill](../../trash-bin/SKILL.md)记录路径、实际 SHA-256、来源与用途决定。无清扫授权时保留原位；当前任务已有明确清扫授权时，对核实可弃用项按该 Skill 预览并实际搬移，不能用“整理仅登记”搁置已授权清理。用途未明或仍有依赖的项原位保留并记待处理，不把全部过程文件一律当作垃圾。

## 正式结果独立于过程目录

正式结果必须独立可用；过程目录的移动、清理或后续写入不能影响已交付结果。此约束从生成时执行，不等清理时才补救。

- 题文、答案、公式、配图、运行数据以及交付要求必需的来源证据，保存于项目正式数据、资源或证据目录。正式读取路径不得指向临时转换、调试、迁移 runtime 或批次工作区；目录联接、符号链接和动态拼接路径同样核实真实目标。正式共享依赖可复用，不要求复制全部环境或历史材料。
- 从过程区采用内容时，经项目原有写入流程保存正式版本，更新实际消费引用并回读，保留身份、来源、内容哈希及必要版本区别；不能只改路径字符串、用指向过程区的链接充当独立副本，或让过程继续写入改变已采用内容。历史资料和在途任务不得擅自搬移或覆盖。
- 检查分清三种情况：实际运行会读取的依赖、交付要求必需的可追溯证据、仅留存的历史路径/批次身份。前两者必须有正式保存位置；第三种不等于运行依赖，不据一个引用要求保留整个过程目录，也不删除历史身份来掩盖依赖。未知项明确待核。
- 验收优先在隔离副本或限制过程路径读取的环境中，实际打开或调用正式入口，核对内容及必要资源；不得为测试重命名、断开或删除正在使用的真实过程目录。仅搜索路径、HTTP 200或静态检查不能证明结果独立，未做隔离读取时报告“静态检查完成，独立运行待验证”。复用仍适用的既有证据，只重验受影响入口。
- **隔离测试禁止整库复制大体积只读共享数据集**：面向百 MB 级共享索引、网站数据包或只读资产库开展多视角隔离测试时，禁止在每个隔离任务目录完整复制全量副本；优先共享同一只读基线（或只读目录联接、基线服务入口），只在隔离区写入本次变更差量与输出。
- 新产物不满足独立性时不能判定完整交付；历史任务发现问题先列出具体依赖、影响及待迁入的正式位置，按当前授权修复。没有修改授权时只报告，不自动迁移或清扫；独立性通过也不自动授权删除过程文件。

### 新批次的混放增量核查

1. 首次写入前按正式入口约定确定正式目录和任务过程区。 复用已有批次计划或生产程序的输出规则，为各类输出指定实际写入位置，并在原写入／接收回执记录真实落点，供关闭前按路径和引用核查。正文、正式配图及必需的最小回执进入正式目录；浏览器截图、详细检查报告、预览、调试输出进入过程区。正式引用若实际依赖其中某项，先查明必要性与稳定路径，再按正式写入流程处理。
- **同一正式目录切换产物结构时，接收前先对账。** 用程序比较旧正式目录快照、本批候选输出清单和现行候选的精确引用，逐项列出现用资源、应入过程区的产物、已被替换的旧文件和用途有疑问的文件。校验必需资源完整，拟退役旧文件已无正式引用且有可恢复去向；有共享引用或独有源内容的项继续保护。优先复用已有暂存与接收检查，阻止已确认过程产物随候选发布。接收后按真实回执回读正式目录、受影响入口和旧文件去向；只要回执或目录有异常，就保持受影响批次待核。回读记录注明实际环境、正式入口引用的逐项内容核对结果，以及被替换旧文件的可恢复去向。只检查本地入口时，单独标记发布产物待核。
2. 用程序读取本批写入或接收回执，按其精确路径、预期版本和正式消费者生成检查清单。对变化的归档索引同时检查其受影响条目与依赖，包括索引新增引用的既存路径。在实际受影响的正式目录内，利用已有提交前清单和收尾目录清单、或可核明覆盖的事务写入记录，对账新增、替换与移除；将实际变化中回执漏列的路径单列检查。同时读取本批正式索引新增的引用，覆盖指向既存文件的情况。无可比基线且写入记录无法证明完整覆盖时，检查本批实际落点和当前引用并记录覆盖缺口，不据回执通过宣称无混放。修改时间仅用于筛选；复制、替换保留原时间时仍按路径与已有版本证据核对。排查限本批实际写入和受影响的共享入口。
3. 引用目标、文件版本和前提未变时复用原证据。本轮范围扫描完整且待核条目已另行登记后，把扫描**开始时刻**作为下一时间筛选下界，包含边界；保留批次及版本标记去重。中途失败、待接收或检查时仍在写入的批次保留待核条目，下一次按批次或回执回读，不能因为跨过时间下界漏掉。待核项有可靠版本证据且文件、声明与判据均未变时，沿用原待核结论；收到接收回执或发现相关版本变化时复核受影响项。
4. 仅对确认混放的文件记录批次、精确路径、实际用途及正确写入位置，交当前执行者修生成入口。用下一批实际回执核对正式路径与外部过程产物去向，通知或规则更新不能代替回读。回执未写、用途未知或仅有后缀线索时按待核保留；整理授权和现有业务门禁照常适用。

## 收尾顺序

1. 从本轮变更记录或用户指定历史范围列文件，先核五类保留集合，再按正式接入判据区分过程在用、已核实停用及用途待核；弃用和删除资格另判。保留此前有效成果，不覆盖原件或其他任务文件。
2. 对需要归位的确认采用文件，检查已知代码/脚本/配置/文档引用、用户已收到的链接，以及是否正被运行任务写入或使用。依赖未知、正在使用或已交付链接不能可靠更新时，保留原位并说明具体原因；“没搜到引用”不单独证明无依赖。
3. 只有确认可移动且在本次授权范围内的文件才归位。先预览精确源/目标，核验绝对路径在本项目内；拒绝意外目录联接、符号链接、目标已存在或跨盘搬移。经上文核实并明确登记的过程兼容入口另行验证。跨盘迁移单独处理；Windows 用原生文件工具和 LiteralPath，不能串 shell 拼接文件操作。
4. 移动前保留长度与 SHA-256；移动后核对实际目标、完整哈希、原路径状态，并修正本轮受影响的引用。对涉及程序路径的改动运行相应读取或构建检查；文档和网页引用用实际目标核验，不只检查文本存在。任一检查失败即停止相关移动，保留可恢复状态，报告未完成项。
5. 复用项目已有记录，追加必要的源→目标、哈希、原因及实际结果，供恢复使用；没有现有记录且确有移动时才创建一份 `.work/<任务名>/整理记录.json`。同任务重试追加真实结果，不重复搬移，不给每轮创建新报告。候选清单由垃圾桶 Skill 管理，不复制出第二套。
6. 最终交付链接只指向已验证存在的文件。通常一句话交代成果位置；只有确有未归位文件、引用问题或失败时说明。无变化则不专门汇报“已整理”。

## 可执行收尾门禁

项目已有收尾检查入口时，交付前实际执行并保存结果。失败项按实际记录，保留可追溯的文件、版本、核验及恢复证据。

## 完成条件与恢复

实际处理的文件数量和位置与记录一致；确认采用的产物可读且引用有效；来源不明和弃用文件保留原位并按需标记；没有移动原始资料或其他任务依赖。不能把“已分类”写成“已完成移动”。

需要撤销归位时，以整理记录和实际哈希为准，先预览反向路径；原位置已有文件或目标已变化时停止，禁止覆盖。清扫或永久删除另行遵循用户授权和垃圾桶 Skill。

## 决策示例与验证边界

- 成品 PDF 和已采用的两张预览图散落根目录：引用可更新时，分别归入交付位置和任务工作区，核哈希并更新链接。
- 已弃用的测试截图：只登记垃圾桶候选，保持原位；即使名为 tmp 也不自动搬移。
- 网站读取中的 JSON 或已经发给用户的附件：保留原路径，优先以后生成到正确位置；不能只移动文件而让现有入口失效。
- 纯问答、重复收尾、共享目录中其他任务文件：分别跳过、不重复移动、保留其他任务文件。

以上为本版已核对的规则场景，不代表在所有项目实测通过。真实整理以各任务的实际文件及引用验证记录为准。

材料库入库及其清理/维护收尾统一使用 `retention_mode=material_only`，不能回退旧宽松策略；用户已明确清扫时直接按现有授权执行，不仅登记候选。复用最终摘要和必要恢复映射，不另建整理报告。门禁通过只证明所检查条件，不能替代文件必要性判断。
