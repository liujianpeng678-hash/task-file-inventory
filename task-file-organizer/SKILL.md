# 整理 Skill

## 普通收尾

1. 首次生成文件前按[开工前分区并标记](references/归位与验收.md#开工前分区并标记)先创建或落实原材料、结果文件、结果数据、工具、垃圾堆五个项目目录，再按任务类或工具类标记过程批次。复用用户指定目录、已有工作区和批次标记。另起项目时核对 E 盘既有分类位置。最终回复前按本轮变更清单收尾。无文件变化即可结束。
2. 核对成果、源文件、必要依赖与配置、个人数据、必要工具。用真实入口或采用记录确认哪些内容已接入。原件、共享任务、在用材料、必要恢复凭据和用户已收到的路径都要保护。可控过程产物从生成起写入相应垃圾堆批次。历史候选与弃用项由[垃圾桶 Skill](../trash-bin/SKILL.md)原位登记。
3. 文件已在正确位置时直接验收。复用仍适用的证据，实际打开或运行受影响的正式入口和项目已有收尾检查，核对内容、必要资源、交付链接和所涉构建。正式消费者读取的代码、数据与必要证据要有稳定位置。需证明独立性时，用隔离副本或限制过程路径读取的入口验证。记录实际覆盖及未验项。
4. 确有文件需要归位时，先读[归位与验收](references/归位与验收.md#收尾顺序)。只移动已确认采用且引用安全的项，核实精确源与目标、并发写入、链接和覆盖风险。预览、核移动前后长度与 SHA-256、更新并实测引用，把去向和恢复依据补入原记录。无搬移时免建整理报告。

## 专项入口

- 项目备份按[项目备份保留](references/归位与验收.md#项目备份保留)核对，`结果数据/备份/` 最多留最近五份仍需使用的备份，确认不用的归入所在盘的垃圾堆。

- 交付新安装包或同一成果的新版本后，按[垃圾桶 Skill 的五版保留规则](../trash-bin/SKILL.md#安装包与迭代交付保留五份)核对版本并归堆超额旧版。
