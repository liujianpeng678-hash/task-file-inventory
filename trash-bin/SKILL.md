# 垃圾桶 Skill

## 普通文件操作

只核对本轮产生或改变的文件。保留已采用成果、源文件、有效依赖与配置、个人数据、必要工具、在用与恢复材料。已知用途的预览或日志按实际用途记录。在用、必要或待核文件各留原位。

新建已明确用途的过程批次时，按[开工前分区并标记](../task-file-organizer/references/归位与验收.md#开工前分区并标记)使用对应垃圾堆。可运行 `scripts/open-process-batch.py` 建批次并登记「处理中」。同批标记与清理候选清单分开，转「可清」后仍按本轮授权筛选。既有未确认文件沿用原位登记。

有弃用或用途未定项时，将相对路径、实际 SHA-256、原因、`generatedThisTask` 和 `useDecision` 合并到任务的 `.task-trash/candidates.json`，保留其他任务条目。`keep`、`discard`、`unconfirmed` 分别表示保留、已弃用、待定。普通操作到登记为止，无候选即可结束。已核用的验收回执留在既有过程区。

## 安装包与迭代交付保留五份

用户明确授权在每次产出新安装包或迭代交付物并核验可用后，顺手轮换本次交付目录里同一产品、同一平台或渠道的版本。按版本号或可信交付记录保留最新五份，少于五份全留。一个版本的程序及其必要配套文件合计一份，整套移交。

第六份起，核对旧版已被替代且无在用、依赖或恢复用途后，按[清扫与恢复](references/清扫与恢复.md#明确清扫读取清单--补查漏记--核对--预览--搬移)直接搬进源盘的可恢复垃圾堆，保留回执，无需再次确认。正在运行、被引用或必须保留的版本先留原位，记明原因，等下次该系列交付时复查。轮换范围是本次交付系列，受保护的源工程、存档、共享依赖和其他项目继续遵循原规则。

## 按本轮授权办理

清理或归堆完成后，按任务文件清单 Skill 的「清理后的剩余量」口径汇报这次范围内实际处理量和处理后的剩余量。

<a id="清扫时逐路径标记2026-11-16-用户确认"></a>
- 明确要求清扫或撤下指定交付件时，先读[清扫与恢复](references/清扫与恢复.md)。在指定范围只读补查，按用途和处理状态分别标记，核对来源、真实消费者、哈希与在用情况。保留待核项，预览执行清单后用同一清单搬入[源盘的可恢复垃圾堆](references/清扫与恢复.md#垃圾堆去向)。报告实际搬移数、字节、回执和未核范围。
- 要求恢复时，从同一份[清扫与恢复](references/清扫与恢复.md#恢复)读取批次回执和精确原路径，先预览再恢复，核验原位置与内容。遇到冲突、越界、链接或哈希变化保留现场。
- 堆内永久删除须用户明确要求彻底删除具体项。执行前核实授权、真实路径、内容身份、在用情况和保留范围。「删了吧」接在交付后按可恢复撤下处理。原位置的缓存、工作树等专项清理按其明确授权与[永久清理条件](references/永久清理.md)办理。
- 永久删除需要使用者明确授权；按[永久清理条件](references/永久清理.md)核对精确清单、引用和保留范围。
