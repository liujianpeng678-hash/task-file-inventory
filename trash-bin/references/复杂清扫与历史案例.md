# 复杂清扫与历史案例

文中的脚本路径从本 Skill 安装目录解析。

### 大型数据引用与局部清扫验收效率（2026-11-15）

大型 JSON/JS 投影的精确路径检查，先按实际字符串语法一次提取、解码并规范化路径集合，再与候选集合匹配；避免逐候选重复全文搜索或仅为路径检查构造整个巨型业务对象。仅限已确认以该语法保存路径的格式；转义、动态拼接或未知格式不能据此断言无依赖。未命中仍不是独立删除依据。

仅删除精确文件、未移动目录且无共享实体影响时，内容SHA及正式入口回读覆盖原件、正式结果、相关依赖和保留主副本；其余未参与操作的文件可核身份、大小和修改时间，不为凑全目录哈希扩大验收。元数据核对不等于内容校验，分别计数。目录整体退役、硬链接关联、并发变化或已知损坏等风险仍需相应专项检查。长分类先保存候选及已核基线，耗时阶段输出进度，避免一次末尾落盘导致中断后全量返工。


### 来源元数据与交接产物清单的区别

核对原件前先看实际数据类型及字段用途：`sourceFiles`、原件元数据中的 `files` 与交接回执中的通用 `files` 不可直接混用；后者可能列脚本、核验JSON和截图，旧SHA不符不能直接报告“原始试卷损坏”。列表／字典、单SHA／SHA列表先按真实结构分支，来源角色和实际输入消费者共同决定原件身份；本批的PDF／Word类型不能推广为所有项目的原件扩展名白名单。生成副本须有输入→输出或内部呈现记录等证据，未证明可弃用的不同版本集中保留。


### 从真实资料生成的旧测试库

测试目录可能复制真实个人数据，不能按名称认定为合成数据，也不因来源真实就保留每个测试副本。先定位独立保留的种子和实际测试生成代码，在不启动服务、不改业务数据的计算中重建明确测试输出，按完整字节 SHA 匹配；只有精确符合已知生成逻辑、保留种子稳定且无在途/固定消费者的副本，才能进入原授权下的清理范围。不通过猜测删除字段、标题后缀或语义近似来证明可重建；未匹配版本、配置、数据库及源码继续保护。现行测试从过程区读取的固定输入另列必要依赖，不随同目录清理。


## 已确认整体弃用目录的快速清理（2026-11-04）

用户明确用“删掉过程区是否影响正式结果”确定清理边界，并要求其余全删时，优先从正式入口反查实际读取依赖和交付必需证据：先将必要内容独立保存、更新实际消费者并验收，再整体退役指定旧过程区。原始资料按身份和内容哈希保护；旧批次 keep 标记、未完成的旧验收、没有现行消费者的恢复脚本及历史报告引用，不自动构成逐文件保留理由。未获整体弃用授权、原件仍混在其中或另有明确要求保留的在途任务时，不套用本分支。

全量读取和隔离结果已通过、代码和数据前提未变时复用，不为每批旧输出重跑整库。永久删除仍须明确授权、核实真实根及全部链接边界；已确认整目录均退役时，采用精确路径和实体/元数据清单，不为即将丢弃的每个过程副本额外读取内容SHA。删除后从旧目录真实不存在的新进程核对正式结果及必要资源，不能只凭HTTP200或缓存响应宣称独立。旧队列及旧候选退役不等于题目数学审核通过。

当用户明确整体弃用一个任务/过程目录，且已核实题目、交付物和外部依赖已独立保存，可用`scripts/move-directory-to-trash.ps1 -Root <真实项目根> -Manifest <精确目录清单>`预览，再加`-Apply`同盘原生搬移。不能因为目录名像临时目录就自动采用本分支；未确认整体弃用时仍用逐文件流程。支持项目既有`99 垃圾堆`或任务`.task-trash`，在清单中明确物理`trash_base/trash_root`，拒绝目录联接作为目标；不跨盘、不覆盖、不永久删除。


清单包含`root`、`trash_base`、`trash_root`及`directories:[{source,target,tree,cleanupApproved:true,useDecision:discard,provenance}]`。`tree`由只读`directory-tree.py <真实目录>`产生；包含根文件身份、全部相对路径/实体/大小/mtime/属性指纹与文件数、字节数，**不是逐文件内容SHA**。此分支执行的是同盘目录重命名，不复制或修改子文件字节；预检、执行前和执行后检查身份与完整元数据指纹，不得以此代替正式交付物的内容SHA验收。

链接、占位符、Git/受保护配置、越界、嵌套重复候选、目标冲突或清单后变更均拒绝并停止。目录内原有`.task-trash`及恢复清单随已明确弃用的父目录原样保存，不清空或重写它们。先核必要附件，再整体移除；执行失败保留逐目录日志并据真实状态接续，不盲目重试。同盘整目录使用原生目录重命名（如 `[IO.Directory]::Move`），不要用可能递归移动子项的 `Move-Item` 代替。接续先核源、目标、链接、原实体和回执；目标存在不代表完整成功。源目标均为实目录时按部分搬移留置，不能跳过、覆盖、删除任一侧或重建基线冒充通过。占用项只保护受影响范围，不强关业务进程；其他保留文件并发变化时如实列差异，不覆盖或计为哈希通过。恢复使用同一清单加`-Restore`先预览，再加`-Apply`；原位置已出现内容则拒绝覆盖。


## 大清单的Git保护检查（2026-11-04）

本机大批量已拆材料清理发现：非Git工作区逐文件启动Git进程造成明显等待。`move-to-trash.ps1`现先逐级检查候选真实路径的祖先目录是否存在`.git`文件或目录；存在Git元数据或设置了`GIT_DIR`／`GIT_WORK_TREE`时，仍执行原有逐文件Git跟踪保护与失败拒绝。非仓库不启动无意义的Git进程。不缓存阴性结果，以免遗漏新增嵌套仓库。哈希、重解析路径、越界、覆盖和可恢复回执检查不变。


## 过程文件保留判定纠正（2026-11-10）

旧 keep 清单、审计记录和关闭凭据缺失，只是待复核线索，不能单独作为全部过程文件永久保留的依据。先核对原件、正式成果、唯一内容版本及当前有效读取路径；完成证据采用实际依赖核查，不能把某个旧脚本未写关闭字段等同于所有产物仍在使用。

当前内容出现 contentBatch、任务号或来源批次名，不等于依赖同名目录中的每个文件。区分业务身份、具体文件引用和执行代码的动态目录读取；保留业务 ID，不因一个批次标签而整目录豁免。只搜到目录名不够证明该目录下所有大快照仍有依赖，同样，未搜到引用也不能单独证明可以删除。

用户明确授权永久删除时，旧修改前备份、恢复验证等过程副本若与保留版本完整 SHA 相同，且已核实具体引用、在用情况和保留副本稳定性，可以只保留每个不同内容版本的一份，删除冗余路径。不能误删唯一版本或替换为近似内容；保留删除路径→主副本→SHA 映射，并说明旧过程路径已退役、需要复跑旧路径型验收时可重建，不假称旧路径仍可读。必要时锁定主副本与待删文件以拒绝并发写者，核验后再删除。


## 待验收批次中的已替代副本（2026-11-15）

待验收或在途状态不能单独证明批内所有文件仍必需。逐项区分当前提交、候选与恢复输入，以及已被替代的旧快照。清理后保留原审核状态，不把文件清理当作业务验收完成。

对已提交但尚待网页验收的初始快照，先核提交回执与现行计划的SHA绑定、当前执行和恢复消费者，再按项目真实数据结构核替代版本完整保留题目、题源、图片声明、历史身份与必要定位；不同或独有内容、绑定不符及未知项保留。只有已证实替代且不影响当前执行/恢复的精确旧快照可单独进入可恢复清单，提交未完成或实际恢复消费者仍读取的提交快照、完整候选与恢复断点继续保留。正式回读已完成时，单独核对实际提交分支、续审入口、恢复依赖闭包、正式原件与结果、历史ID及计划回执绑定；证实不再被消费的事务写入快照可独立退役，不必等待整个网页验收结束。仅在永久删除授权范围内执行永久删除，不改业务审核状态，不连带删除原件、在途候选或必要恢复输入。内容包含核对不等于文件SHA相同，不据此自动永久删除不同字节版本。




## 有现存源码的 Python 字节码缓存

仅用于用户已授权清扫的精确 Python 模块目录；不据 `.pyc` 后缀清空环境。源码、解释器、原生库、模型、离线安装包及用途不明项保留。

- 先读取当前容量和既有删除回执，再由所属解释器确认版本、cache tag 与 magic；使用 `-S -B` 做静态校验，不导入目标库、不执行转写或业务源码。不同环境分别校验，不能套用另一个 Python 版本的计划。
- 源文件名可能含点号：从候选反推精确 `.py`，再用 `cache_from_source` 正向验证；反推 API 拒绝带点名称不等于源码缺失。默认版本/优化级别以外的缓存未验证就保留。
- 只清理普通、单硬链接缓存，逐级排除重解析点。共享缓存目标先排除，不将删一个别名算释放实体；配对源码可以是受保护共享文件，只读比较，不修改其任何链接。
- 用原解释器核缓存头与当前源码时间/大小，静态编译比较代码对象（仅统一编译来源路径，递归处理嵌套代码）；同时记录源码与缓存 SHA、身份、长度和修改时间。不要用访问时间判断读取期间是否变化。无法证明源码等价或自带无源码字节码时保留。
- 执行前固定计划哈希和精确范围，重核单链接、源码/缓存 SHA 与修改时间、占用及目录边界；逐文件 LiteralPath 删除，禁止裸递归。已有回执就接续，不重跑；遇并发变更或占用失败，仅跳过受影响项。
- 删除后核源码和解释器 SHA，分别登记实际缺失、重建及跳过项。不要重复清扫运行后重建缓存；逻辑删除量与空闲空间净变化分开报告。静态源码等价不代表业务功能已运行验收。
