# 永久清理

文中的脚本路径从本 Skill 安装目录解析。

## 用户明确授权永久清理过程文件时

本分支适用于当前任务中明确授权永久删除的范围。历史文件和范围外的普通清扫沿用[可恢复清扫流程](清扫与恢复.md)。删除前核对精确路径、文件身份、用途和所有硬链接。原件、结果、运行依赖、有效回滚及验收证据、用途未明项继续保留。

- **可重建缓存**：先确认真实缓存路径、作用及在用进程，再优先使用包管理器原生清理，例如 `pip cache purge`、`npm cache clean`、`pnpm store prune`、绑定精确 GOCACHE/GOMODCACHE 的 `go clean -cache -modcache`。不为已证实无独有内容的下载/编译缓存逐文件读取 SHA，避免大量小文件反复核验。保留已安装依赖；不强制清理包管理器未知目录。
- **过程 Git bundle**：仅删除已核实可重建副本。正式仓库完整性检查通过，bundle 自身可读且 verify 通过，全部提交可达且精确本地引用保留，再核对独立远端对应引用；缺少任一依据则保留。记录路径、SHA、引用及提交映射，不能因名字含 backup 就认定弃用。
- **临时 Git 工作树**：必须走 Git 工作树管理流程，不能用普通垃圾搬移或裸递归删除。核对 Git 注册、干净状态、未跟踪及忽略文件、未被运行任务使用，以及 HEAD 已被正式引用和独立远端保留。非可重建缓存的忽略文件仍算独有候选，保留。使用 `git worktree remove`，不加 force；执行前再验状态和引用，拒绝或变化时停止该批。清理后核对注册表、剩余路径、保留提交和正式分支/标签。
- **已闭环过程区与孤儿对象池**：对已合并交付且独立运行验证通过的历史任务工作区（`_worktrees`、`_qa_sandboxes`、`_previews`、`.work` 及同盘 `.task-trash` / `99 垃圾堆`），在用户明确授权释放空间时按实际清单彻底删除，不因“曾放进同盘垃圾堆”长期留占空间。清理硬链接快照池（如对象池/备份对象目录）时，在删完上层过期快照后，用 `os.stat(p).st_nlink == 1` 反查不再被任何保留版本或正式入口引用的孤儿对象并同步清理，保留有效引用及跨目录联接目标。
- **空间与停止条件**：按清理前后实际可用空间报告净变化，注明并发任务影响；不把逻辑大小、硬链接多路径之和或同盘搬移当成释放量。满足已核实批次验收后交付，未知项单列，不为追求更大数字删原件。自动审批拒绝时保留拒绝事实，只在工具本身提供更窄且安全的原生方式时继续，不绕过拒绝。
