# 清扫与恢复

文中的脚本路径从本 Skill 安装目录解析。

## 五类保留与电脑清理边界

遵循[整理 Skill 的五类保留标准](../../task-file-organizer/SKILL.md#保留区与过程垃圾堆2026-11-15-用户最终确认)：结果文件、源文件、必要依赖与配置、个人数据、必要工具。它替代旧三类口径，不要求搬动保留内容。先核五类及系统、仍用软件，再核清理候选；项目结果反查不能覆盖个人数据或独立工具的全部用途。

五类之外只是候选，须核实弃用、独有内容、恢复需要和在用情况；未知项原位保留。不得整删 Documents、AppData、`.cache`，不得把最近未使用的关键工具或必要离线安装包直接当垃圾。容量调查、讨论保留原则或迭代规则不授权清扫；明确清扫与永久删除分别沿用下文授权分支。整盘调查不触发整盘自动清理，清扫须落到核实后的精确范围。

## 垃圾堆去向

- 清理哪个盘，就归入哪个盘已有的自建垃圾堆（例如项目 .task-trash 目录）。一次涉及多个盘时按来源盘分别归堆、记录原路径。用户明确给出垃圾堆位置时按指定位置处理。
- 「垃圾堆」指可恢复的自建目录。用户明确指定 Windows 回收站时才使用系统回收站。跨盘归堆、清空或永久删除按当轮明确授权执行。
- 同盘归堆整理了原目录，文件仍占该盘空间。用户还要求腾出空间时，说明这次实际释放量，沿用已经明确授权的去向和操作。

## 清扫时逐路径标记

- 每次清扫对实际核查或处理的文件、文件夹同步留持久标记，复用当前任务的清扫清单/验收记录。无现成字段时在同一工作区建立一份 `清扫标记.json`，用绝对路径索引，并提供可查看的摘要；不自动重命名源文件、移动保留项、修改目录属性或在每层散放标记文件。用户另有明确可视标记要求时再采用相应方式。
- **先标用途种类，再另记处理状态（2026-11-16 用户再次明确）**：种类固定为①结果文件；②源文件；③必要依赖与配置；④个人数据；⑤必要工具；⑥已核实无用的过程文件／垃圾；⑦用途待确认；⑧过程文件。以实际用途和证据判断，不按后缀、名字或所在目录猜测。“保留、待清理、已归堆、已永久删除、受阻”是处理状态，不能充当种类；“部分核查、已检查”也不是种类。
- **已知用途与采用／退役状态分开**：已核实为渲染预览、检查图或中间输出，但采用状态、生成依赖或退役资格尚未核清时，种类标“过程文件”，另记“当前预览／在用／保留待核”等状态；不能因未正式采用一律写“用途待确认”，也不能因属于过程就归垃圾。真实消费者仍需的媒体可主列“必要依赖与配置”、附加“过程文件”；原始资料和个人数据保持原类别。只有用途本身缺证据才用“用途待确认”；核实停用并满足授权后，才转为“已核实无用的过程文件／垃圾”。第5—7期88个原始素材、当前预览与HTML媒体依赖已按实际引用和保留SHA/身份验证此区分；未据此宣称正式采用或独立运行通过。
- **混合文件夹单独标“混合”**，在 `contained_categories` 列出已核实包含的种类，并继续细分实际核查的子目录/文件；未核子项仍标“用途待确认”，不因父目录属于工具就把其中全部文件当工具，也不因含垃圾就整目录清理。一个文件有多种用途时记录主要种类及附加用途，满足任一保留用途仍须保护。文件/文件夹类型与用途种类分字段记录：`type` 为 file/folder，`classification` 为上述种类或文件夹的“混合”。
- **核查覆盖另记**：未核查、仅容量统计、部分核查、全部用途核查完成。只统计大小不能标已清扫，清理部分子项不能把父目录标完成。仅容量统计时用途先标“用途待确认”；正常清扫不延伸到无关文件，未列入范围不代表已核查。
- 标记至少含路径、文件或文件夹类型、用途种类、用途/保留原因、执行状态、覆盖范围、证据指针和核查时间；已搬项记录原路径与垃圾堆路径，删除项绑定实际回执及结果。路径缺失不自动等同已删除。共享文件沿用原责任者记录，不覆盖其他任务状态。
- 下次清扫先读既有标记，从未核、部分核查和待处理项接续。复用判断前核路径身份、内容或长度/mtime及依赖前提是否变化；只有未变范围复用，改变项重新核实，不能凭旧标记自动删除。继续遵守原授权，不因标记“可清理”扩大为永久删除权限。
- 汇报分别给出检查范围、已处理量、未核项、归堆量与实测释放量。保留项无需为了凑清理量反复检查；仍有未核或受阻项时，整体标部分完成。

## 项目过程材料清扫：先从结果反查

用户要求清扫项目、大任务目录或继续处理下一个大文件夹时，沿用已确认范围和授权，先用本节判定用途，再进入下文对应的搬移或永久删除分支；不先按体积、重复路径、备份版数或旧 keep 清单决定删留。纯容量查询只读调查，日常操作仍只登记。

1. 从当前正式结果、实际展示/运行入口开始，沿代码、配置、数据引用及来源记录，反查其直接和间接依赖、原始材料、身份与必要题源证据，形成精确的“结果→依赖/原始材料”映射。结果文件本身不一定包含全部依赖，不能只留一个最终文件。共享依赖仍放正式共享位置，不为分类重复复制。
2. 按任务目录或同类产物集合分类，分组与混放例外遵循[整理 Skill 的批处理规则](../../task-file-organizer/SKILL.md#大型历史项目整理结果反推与任务批处理2026-11-18)：原始材料；已正式接入的结果及必需依赖；过程在用；已核实可退役的过程材料；接入/用途待核。正式消费者仍需的配图、数据与工具不能当垃圾；必要来源证据按保护要求保留。旧修改前快照、调试脚本、恢复测试、报告和日志不因交付、验证通过、“可供历史重跑”或旧keep标签自动升级为正式结果/依赖；旧成果备份也不因名为“原始版本”就等同于原始输入。
3. 对映射之外的产物先用任务清单、实际生成规则及当前使用情况核清整组用途，充分证据覆盖整组时批处理，混放与未知子项再逐文件核查；“不在映射中”“未搜到引用”只是候选线索，不单独构成删除依据。结合正式结果回读、原始材料完整性、实际消费者及任务状态，确认其已经失去用途后归入过程清理清单。在途候选、未提交内容、现行恢复断点和无法判明的项保留；问题仅影响某个子范围时，排除该范围后继续已核实项。
4. 如正式结果仍读取过程目录，先按[整理 Skill 的正式结果独立规则](../../task-file-organizer/SKILL.md#正式结果独立于过程目录2026-11-15-用户确认)保存必需内容、更新真实消费者并回读，之后才能清理。必要追溯证据保留；仅出现的历史路径、批次身份不等于运行依赖，也不得删除历史身份来掩盖依赖。
5. 把已核实弃用的过程材料按精确清单集中到任务局部垃圾堆，保留源→集中位置与实际操作回执；普通清扫到此可恢复保留，已有明确永久删除授权时继续删除，不重复索要同一确认。分类或预览不算完成清扫。先保护仍需使用的结果与原始材料，不能为了验证依赖而移动正在使用的目录。
6. 硬链接按实体检查全部路径：删一处别名不等于释放数据；只有没有其他保留链接、原件、有效依赖或明确保护项时，才能在授权内连同精确关联的孤立对象删除。Windows 下校验真实硬链接数必须调用 `os.stat(p).st_nlink`（`DirEntry.stat().st_nlink` 恒为 0 不可信）；识别目录联接等重解析点须检查 `FILE_ATTRIBUTE_REPARSE_POINT`（`0x400`），不能仅靠 `os.path.islink()`，避免误穿透；清理空目录前须反查外部有效联接是否指向该目录并保护占位，避免联接悬空；深层超长路径缓存须启用 `\\?\` 前缀并配合原生 LiteralPath 操作，锁定清理末尾仍存在的路径以防 delete-pending；已删回执与真实路径一致时接续剩余项，不重做已成功删除、不改ACL规避拒绝。
7. 用新进程从正式入口回读受影响结果及资源，核保留原件/身份、内容哈希、删除路径和磁盘实际净变化；没有运行独立性验证时明确其缺口。报告本批分类与执行范围、待核项及未处理部分，不将某类快照清完说成整个目录已清完。


## 明确清扫：读取清单 → 补查漏记 → 核对 → 预览 → 搬移

先完成上文适用的结果反查与用途分类，再判断清理粒度：用户已明确整体退役指定过程目录时，采用[已确认整体弃用目录的快速清理](复杂清扫与历史案例.md#已确认整体弃用目录的快速清理2026-11-04)；不把逐文件旧报告核查作为该分支的额外前置条件。普通局部清扫使用以下逐文件流程。

1. 确定用户指定或当前任务的具体目录。复用已有范围，不自动扩到整盘、用户根目录或其他项目。范围确实不明才询问。修复本 Skill 只授权隔离测试，不代表清扫真实项目。 用户要求清理旧过程区时，应检查该旧过程区，不能擅自缩为本轮临时脚本；部分处理时明确实际目录、数量和未处理范围。
2. 即使清单缺失或为空，也必须在该范围进行只读检查：
   ```powershell

   & '绝对skill路径/scripts/inspect-trash.ps1' -Root '任务目录绝对路径'

   ```

   默认最多 2000 个文件、6 层深度；可按明确范围调整 `-MaxFiles`、`-MaxDepth`，以及通过 `-Manifest` 指定已有清单。它输出未登记项、有效登记、依据不足、内容变化、未见路径、保留项、受保护项及检查缺口，不写文件、不自动选垃圾。依赖目录、Skill 配置、Git 元数据与垃圾堆不递归；链接不跟随。截断、无法读取、排除范围都必须报告，不能称为全量扫描。
3. 对未登记项结合任务记录、实际用途、交付链接、引用和运行依赖核对。目录名含 tmp、文件很旧、没有搜到引用，都不足以证明可清理。对尚不明确的文件原位保留，列为待判断；对未见的登记路径检查精确路径与已有回执，区分已搬走、已恢复、失效和未检查。不能盲目重试或重建哈希掩盖内容变化。
4. 补充有证据的遗漏记录。历史文件不必伪称本轮生成：只有本次清扫范围明确包含它、已核实弃用时，使用 `generatedThisTask:false`、`useDecision:"discard"`、`cleanupApproved:true`，并在 `provenance` 写明实际来源/弃用依据，在 `reason` 写明清理原因。`cleanupApproved` 必须来自用户本次授权及实际核查，不能因为发现文件就自行赋值。历史用途未定、无依据的文件不能清理。
5. 保留原始候选清单，从已核实项生成本次执行清单（仍放在任务 `.task-trash/` 下）。问题项留在候选清单并报告原因，不让一个失效项遮蔽所有其他可处理项。对执行清单先预览：
   ```powershell

   & '绝对skill路径/scripts/move-to-trash.ps1' -Root '任务目录绝对路径' -Manifest '执行清单绝对路径'

   ```

   预览成功且符合授权后，以相同清单加 `-Apply` 搬移。用户已明确清扫时不再机械重复索要批准。路径越界、Git 跟踪、受保护文件、链接、哈希变化和覆盖冲突仍由脚本拒绝；拒绝时停止该执行批次，查明原因，不绕过保护。
6. 报告并回写原计划：实际检查目录和范围限制；登记/未登记待判断/依据不足/失效或变化/受保护等数量；真正搬移数量与字节数；回执路径；未完成事项。可执行项已搬移、其余仍待判断时，只标已完成的子范围，整体保持部分完成或待处理，不因列出了保留原因就将整个清理任务勾为完成。没有移动就是 0，不把预览算清扫。搬到同盘垃圾堆不代表已释放空间；用户目标包含腾出空间时须明确此目标尚未达成，永久删除仍按[永久清理的明确授权分支](永久清理.md)处理。

**空结果措辞必须准确**：
- 清单缺失或为空：没有登记候选，尚不能判断是否有垃圾。
- 扫描没有可直接执行项，但存在未登记或待判断项：本次未确认可清理项，仍有待核查文件。
- 达到上限或无法读取：只完成部分检查，明确缺口。
- 所有范围内文件用途均完成核查且无可清理项：仅能说“本次已核查范围内无可清理项”，不能泛化为电脑没有垃圾。

## 恢复

```powershell

& '绝对skill路径/scripts/move-to-trash.ps1' -Root '原任务目录绝对路径' -Manifest '批次内receipt.json绝对路径' -Restore

& '绝对skill路径/scripts/move-to-trash.ps1' -Root '原任务目录绝对路径' -Manifest '批次内receipt.json绝对路径' -Restore -Apply

```

保留相对路径与恢复清单，不覆盖已有文件。失败时报告实际完成和剩余状态；不把无剩余操作解释为没有其他垃圾。
